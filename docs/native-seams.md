## Entry, lifecycle, dispatch

- `Headless::new` starts without a document; `with_document`/`ensure_document` runs `file.new`. `open` executes `document.open`, `save` executes `document.save` (requires a path if the document was never saved), and `export` executes `document.export` (crates/mcp/src/headless.rs:88-125,269-289). `Session` can directly `add_document`, `set_active`, `close_document(index)`, or `execute("file.close", ...)`; `close_document` adjusts active tab and discards its recovery copy (crates/engine/src/lib.rs:813-828,856-864,896-918). For `app.quit`, headless only returns null; release the wrapper's handle explicitly (**INFERRED**, crates/mcp/src/headless.rs:294-299).
- A `Session` owns `Vec<DocState>`, active index, preferences, clipboard, command journal, and `Box<dyn Tool>` (crates/engine/src/lib.rs:670-685). Each `DocState` owns an `Arc<Document>`, selection/history, path, format, revision and saved snapshot; undo defaults to 500 snapshots, dirty checks `Arc::ptr_eq` against the saved document (crates/engine/src/lib.rs:64-83,147-180). Tool state is reset on document switch (crates/engine/src/lib.rs:807-835). A `Renderer` holds a reusable render context, decoded images, text and geometric caches and optional raster worker threads (crates/render/src/lib.rs:254-301,378-401). **INFERRED:** serialize calls per mutable handle; `&mut self` dispatch does not promise concurrent calls or a `Send`/`Sync` guarantee (crates/mcp/src/backend.rs:9-16; crates/engine/src/lib.rs:920-936). No Tokio runtime is on the MCP or engine dependency list (crates/mcp/Cargo.toml:11-20; crates/engine/Cargo.toml:11-34).
- Registry is **not** a dynamic trait-object command registry. `CommandSpec` has static string id, description, enablement fn pointer and `Run = fn(&mut Session,&Value)->Result<Value>`; `OnceLock<Vec<CommandSpec>>` concatenates modules; `find_command` does a linear id match (crates/engine/src/cmd/mod.rs:83-106,157-185,270-275). `Session::execute` checks unknown/disabled, invokes its run pointer under a panic guard, journals top-level calls (crates/engine/src/lib.rs:920-948). The registry's actual composition is at crates/engine/src/cmd/mod.rs:157-275; this study did not run the catalogue to recount its entries.
- **Exact desktop control path:** TCP `serve_lines` parses `{id,method,params}` then `serve` sends a `ControlRequest` over `mpsc` and requests egui repaint (apps/vectorcraft/src/control_server.rs:55-67,77-103,139-165); `vectorcraft_ui_egui::control::handle(app,ctx,req)` dispatches `engine.execute` to `app.run(id,params)` (crates/ui-egui/src/control.rs:106-126), whose non-UI branch calls `self.session.execute(id,&params)` (crates/ui-egui/src/lib.rs:435-465). **No desktop function directly accepts a JSON string command and returns a JSON string:** that is a thin candidate wrapper over the existing `Value` API (**INFERRED**, crates/engine/src/lib.rs:920-936; crates/mcp/src/headless.rs:258-271). Desktop adds UI commands to `engine.commands`; headless adds six host aliases (crates/ui-egui/src/control.rs:69-75; crates/mcp/src/headless.rs:24-43,129-135).
- MCP path: `call_tool` validates JSON-object args, `dispatch("run_command")` calls `Backend::call("engine.execute", {command,params})`; errors become `ToolResult {isError:true}` (crates/mcp/src/tools.rs:654-678,807-822). `Headless::call` translates methods to engine commands and stringifies engine errors (crates/mcp/src/headless.rs:114-125,258-300). `Remote::call` instead serializes the same method/params to a JSON line over TCP (crates/mcp/src/backend.rs:85-109). Desktop socket is loopback, at most 16 clients and 4 MiB per request; malformed request closes connection (apps/vectorcraft/src/control_server.rs:18-39,77-103,139-165). No auth handshake in this parsed control path (apps/vectorcraft/src/control_server.rs:77-103,139-165).

## Values, files, and errors across a cdylib

- **JSON-safe values:** command args/results are `serde_json::Value`; `CommandInfo` is `Serialize`; `Prefs`, `Document`, `Artboard`, `Node`, `NodeKind`, `NodeId`, `Unit` and `ColorMode` derive serde (crates/engine/src/cmd/mod.rs:109-119; crates/engine/src/lib.rs:307-310; crates/doc/src/lib.rs:87-100,297-305,313-319,450-465; crates/doc/src/node.rs:12-15,252-254,339-342). `Document` is not sufficient **alone** for image bytes: `ImageBlob.bytes` and `proxy` are skipped by serde, and the native format puts used blobs in a separate base64 `images` map (crates/doc/src/lib.rs:445-455; crates/format/src/lib.rs:1-18,184-204). Keep `Headless/Session/Renderer` as opaque handles (**INFERRED** from their mutable state, crates/mcp/src/headless.rs:9-16; crates/render/src/lib.rs:274-301).
- Byte entry: engine `document.open` accepts `{path}` or `{name,dataBase64}`; `open_bytes_with` adds decoded document to `Session` and reports `{index,title,format,warnings,...}` (crates/engine/src/cmd/fileio/load.rs:205-250,253-273). Native `format::load_file` / `save_with` operates on bytes; `.vectorcraft` is versioned JSON (optionally gzip) with image/profile/preview base64 and decompression limit 512 MiB (crates/format/src/lib.rs:1-23,44-55,83-90,180-204). Export without path returns `dataBase64`, format, byte size and possibly multiple named files/linked blobs; with path writes files (crates/engine/src/cmd/fileio/export.rs:48-57; crates/engine/src/cmd/fileio/mod.rs:795-833). `ui.render` does `raster_size`, `Renderer::render_region`, `Rendered::to_png`; without path gives `pngBase64`, width, height (crates/mcp/src/headless.rs:228-251). Raw `Rendered.pixels` is row-major premultiplied RGBA8; `to_straight` and `to_png` convert and encode it (crates/render/src/lib.rs:170-202). **INFERRED:** expose PNG or base64 on the initial JSON ABI and make a separate byte-buffer ABI only if high-volume pixels warrant it.
- Error model: `EngineError::{UnknownCommand,Disabled,BadParams,NoDocument,NoNode,Other,Internal}` (crates/engine/src/lib.rs:33-53); `DocError` and `FormatError` have their own variants (crates/doc/src/lib.rs:75-85; crates/format/src/lib.rs:75-99). Engine's *top-level* `run_guarded` catches Rust panics, restores the active document/selection/interaction snapshot and returns `Internal`; that is not a guarantee every arbitrary wrapper operation is panic-safe (crates/engine/src/lib.rs:1000-1024; crates/engine/src/guard.rs:1-25). Headless converts engine errors to `String` (crates/mcp/src/headless.rs:114-125), and the desktop uses `{ok,result}` or `{ok:false,error}` (crates/ui-egui/src/control.rs:49-66). **INFERRED:** catch unwinds at every exported cdylib entry, including construction, render, parsing and drop, not only `execute` (crates/engine/src/guard.rs:15-25; crates/mcp/src/headless.rs:228-251).

## Headless and build facts

- Headless is a real in-process path: `Headless::with_document` plus CPU `Renderer`, no egui window; `ui.pointer` takes document-space coords, explicitly rejects screen-space, and `ui.render` emits PNG (crates/mcp/src/headless.rs:88-102,155-183,228-251,258-299). Renderer uses `vello_cpu` for document-to-pixel rasterization (crates/render/src/lib.rs:1-7,18-21). It caps exports to 32,768 pixels per side and 2^28 pixels total; `raster_size` checks before rendering (crates/render/src/lib.rs:33-55). Raster workers can be enabled (`threads`), but no GPU is needed for this CPU path (crates/render/src/lib.rs:274-286,378-401; crates/render/Cargo.toml:18-30). Desktop UI adds egui events and GPU/presentation concerns; those are separate (crates/ui-egui/src/control.rs:183-245; Cargo.toml:66-74).
- Crates are `vectorcraft-engine`, `vectorcraft-doc`, `vectorcraft-mcp`, `vectorcraft-render`, `vectorcraft-format` at workspace v0.4.0, edition 2024, rust-version 1.95 (Cargo.toml:1-11; crates/engine/Cargo.toml:1-6; crates/doc/Cargo.toml:1-6; crates/mcp/Cargo.toml:1-6; crates/render/Cargo.toml:1-6; crates/format/Cargo.toml:1-6). No `crate-type` declaration in those five manifests: **INFERRED** default library artifact, not a ready C cdylib; new wrapper must declare one (those manifests:1-20). `serde` has `rc`, `serde_json` float_roundtrip; render uses native vello_cpu multithreading; engine pulls format, SVG/PDF, render, plugin crates (Cargo.toml:38-56; crates/render/Cargo.toml:18-30; crates/engine/Cargo.toml:11-34). MCP headless adds render/doc/tools without egui or Tokio (crates/mcp/Cargo.toml:11-20). CLI already creates `Headless` for `run` and `convert` and delegates each step via `Backend::call`; no CLI subprocess is necessary for the library cut (apps/vectorcraft-cli/src/main.rs:163-181,224-260).
- No runtime performance, Send/Sync trait, native ABI stability, or built test execution was verified in this study. **INFERRED:** test the cdylib against a real open/edit/save/reopen and `ui.render` pixel oracle before committing to protocol limits (crates/mcp/src/headless.rs:228-289; crates/engine/src/cmd/fileio/load.rs:205-250).
